# order-scout

Помощник фрилансера: собирает новые заказы с FL.ru и Kwork, отсеивает неподходящие, передаёт оставшиеся на оценку и присылает в Telegram карточку с готовым откликом. Отклик на бирже отправляет сам фрилансер — одной вставкой.

```
биржи ──► сбор (каждые 15 мин) ──► фильтр ──► оценка ──► карточка в Telegram
                                     │                       │
                                отсеяно с причиной     «Открыть заказ» / «Пропустить» / «Отправил»
```

## Возможности

- **Сбор без входа в аккаунт:** RSS-лента FL.ru и данные страницы заказов Kwork (бюджет, допустимая цена, число предложений).
- **Фильтр:** слова ниш, стоп-слова, минимальный бюджет, максимум откликов. У каждого отсеянного заказа записана причина.
- **Оценка:** решение «берём / берём этапами / не рекомендую», балл 0–10, срок, цена, риски, текст отклика. Оценщик сменный:
  - встроенный — простые прозрачные правила (демо-режим);
  - внешний — через обмен JSON-файлами (`export` / `import`) со строгой проверкой каждой записи.
- **Telegram-бот:** карточки только с баллом не ниже порога, отклик отдельным сообщением (копируется одним нажатием), кнопки меняют статус заказа, команды `/stats`, `/pause`, `/resume`. Бот отвечает только владельцу.
- **Устойчивость:** недоступная биржа или сбой Telegram не останавливают работу; повторно найденный заказ не дублируется.

## Пример карточки

```
FL.ru · берём · 7/10
Собрать базу земельных участков нужной категории Avito, Cian, DomKlic
бюджет не указан · откликов: нет данных
Наш вариант: 3 дн. · 4 000 ₽
Риски: площадки защищаются от парсинга — часть данных может потребовать ручной проверки
Похожий проект: https://github.com/ZniKDK/web-parser

[Открыть заказ]
[Пропустить] [Отправил]
```

## Быстрый старт (демо, без бирж и ключей)

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
copy config.example.yaml config.yaml

.\.venv\Scripts\python -m order_scout collect --demo     # 8 вымышленных заказов, 4 проходят фильтр
.\.venv\Scripts\python -m order_scout evaluate --rules   # оценка встроенными правилами
.\.venv\Scripts\python -m order_scout stats
```

## Работа с Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) и узнайте свой chat_id (например, у @userinfobot).
2. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` и `CHAT_ID`.
3. Запустите:

```powershell
.\.venv\Scripts\python -m order_scout run           # настоящие биржи
.\.venv\Scripts\python -m order_scout run --demo    # демо: карточки придут сразу
```

## Внешний оценщик

`export` пишет в `data/pending.json` до 30 самых свежих заказов за последние сутки (более старые помечаются «устарел»), вместе с порогом и списком проектов портфолио. Оценщик отвечает файлом `data/evaluations.json`:

```json
{"evaluations": [{"id": 46, "decision": "take", "score": 7, "days": 3, "price_rub": 4000,
                  "risks": "…", "reply": "Здравствуйте! …", "portfolio_url": null}]}
```

`import` принимает только полностью корректные записи (известный заказ в ожидании оценки, допустимые значения, ровно эти поля); остальные перечисляет с причиной, а заказ остаётся в очереди.

## Настройки

`config.yaml` (пример с комментариями — `config.example.yaml`): источники, слова ниш, стоп-слова, минимальный бюджет, максимум откликов, порог балла, интервал сбора (не чаще раза в 10 минут) и проекты портфолио. База, лог и файлы обмена лежат в `data/`.

## Тесты

```powershell
.\.venv\Scripts\pip install -r requirements-dev.txt
.\.venv\Scripts\python -m pytest
```

Разбор лент проверяется на сохранённых обезличенных образцах (`tests/fixtures/`), сеть и Telegram в тестах подменяются.

## Ограничения

- Только публичные ленты; FL.ru отдаёт в RSS сокращённое описание, Kwork — первые 12 заказов страницы.
- Отклики на биржах отправляются вручную: автоматические отклики нарушают правила площадок.

## Стек

Python 3.13, httpx, aiogram 3, SQLite, PyYAML, pytest, GitHub Actions.
